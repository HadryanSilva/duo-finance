# Frontend Web — Implementation Plan (3 de 4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar a aplicação web Vue do Duo Finance — landing com lista de espera, autenticação completa, onboarding, dashboard, lançamentos, contas, categorias, orçamentos, recorrências, configurações e admin — em pt-BR e en, desktop e mobile, consumindo a API dos planos 1 e 2.

**Architecture:** SPA Vite em `frontend/`, organizada por funcionalidade (`src/features/<feature>/{api,components,pages}`) sobre uma base compartilhada (`src/shared/{ui,lib,i18n,api}`) e a casca da aplicação (`src/app`). Os tipos da API são gerados do OpenAPI do backend, nunca escritos à mão. Dados do servidor vivem no TanStack Query; a sessão (access token em memória) vive num store Pinia. Um único cliente HTTP injeta o token e faz um refresh compartilhado ao receber `401`.

**Tech Stack:** Vue 3 (última estável), Vite, TypeScript estrito, Vue Router, Pinia, TanStack Query para Vue, vue-i18n, Tailwind CSS v4, shadcn-vue (Reka UI), lucide-vue-next, vue-echarts (ECharts), VeeValidate + Zod, openapi-typescript, Vitest + Vue Test Utils + MSW, Playwright, ESLint + Prettier. Gerenciador: npm.

**Spec:** `docs/superpowers/specs/2026-11-05-duo-finance-mvp-design.md` (seção 4 — Frontend; seção 3 — API e Segurança; seção 2 — regras que a interface exibe; seção 6 — testes do frontend; seção 7 — LGPD).

**Sequência de planos:** (1) fundação e identidade; (2) domínio financeiro; (3) este; (4) infra e deploy. Este branch (`feature/frontend`) parte do branch com os planos 1 e 2.

## Global Constraints

- Código em `frontend/`; comandos rodam a partir de `frontend/`. Node 24, npm. Dependências na última versão estável no momento do scaffold, gravadas no `package-lock.json`.
- TypeScript `strict: true` e `noUncheckedIndexedAccess: true`; `<script setup lang="ts">` em todo componente; sem `any` explícito (regra ESLint `@typescript-eslint/no-explicit-any: error`).
- Organização: `src/app` (router, layouts, providers), `src/features/<feature>/{api,components,pages}` com as features `auth, onboarding, dashboard, transactions, bank-accounts, categories, budgets, recurring, settings, landing, admin`, e `src/shared/{ui,lib,i18n,api}`. Uma feature não importa de outra feature; o que é compartilhado sobe para `src/shared`.
- Tipos da API vêm de `src/shared/api/schema.ts`, gerado por `npm run api:types` (openapi-typescript) a partir de `http://localhost:8080/v3/api-docs` com o backend no perfil `dev`. O arquivo gerado é versionado e nunca editado à mão.
- Direção visual: cor de marca indigo `#4F46E5`; verde e vermelho só para receita e despesa; amarelo para alerta de orçamento; fonte única Inter com escala tipográfica em tokens; valores com `tabular-nums`; superfícies claras com bordas finas e modo escuro equivalente; logo SVG com dois círculos sobrepostos; sidebar no desktop (`≥ md`, 768 px) e navegação inferior no mobile.
- Todas as cores, tamanhos de fonte, espaçamentos e raios vêm de tokens Tailwind v4 (`@theme` em `src/app/styles.css`). Fora de `src/app/styles.css`, nenhum hex, nenhuma cor `rgb()/hsl()` e nenhum valor arbitrário de tamanho (`text-[13px]`, `p-[7px]`). Um teste de guarda (Task 1) falha se encontrar algum.
- Idiomas `pt-BR` e `en`. Valores em EUR formatados com `Intl.NumberFormat(locale, { style: 'currency', currency: 'EUR' })`; datas com `Intl.DateTimeFormat(locale)`. Valores monetários trafegam e são guardados como inteiros em centavos; nenhum cálculo de dinheiro usa `number` com fração.
- Datas de negócio (`date` de lançamentos, `startDate`, `month`) trafegam como string `YYYY-MM-DD`/`YYYY-MM` e nunca passam por `new Date('YYYY-MM-DD')` (que interpreta UTC e desloca o dia).
- Sessão: o access token fica só em memória (store Pinia); o refresh token é o cookie `HttpOnly` `df_refresh` gerido pelo navegador. Ao iniciar, o app chama `POST /api/v1/auth/refresh` para restaurar a sessão. Um `401` dispara um único refresh compartilhado entre requisições simultâneas, que são repetidas; se o refresh falhar, a sessão é limpa e o usuário vai para `/login`.
- Erros da API são `ProblemDetail` com `code`; a interface traduz `code` por i18n (`errors.<CODE>`), nunca mostra `detail` cru. `errors[]` de validação é mapeado para o campo do formulário.
- `402 SUBSCRIPTION_INACTIVE` em qualquer rota financeira leva à tela "Acesso suspenso" (`/suspended`).
- Frontend e API na mesma origem: em dev, o Vite faz proxy de `/api` para `http://localhost:8080`.
- Commits terminam com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Várias requisições recebem `401` ao mesmo tempo, ou outra aba acabou de renovar a sessão**: um único `POST /auth/refresh` é feito e todas as requisições são repetidas com o token novo. Se o refresh responder `401 REFRESH_RACE`, ele é tentado de novo uma vez após 300 ms, porque o cookie já foi rotacionado pela outra aba, e o usuário não é deslogado. Teste em Task 3 (`concurrent401s_triggerSingleRefresh`, `refreshRace_retriesOnceWithoutLogout`).
2. **Valor digitado com separadores do idioma**: `"1.234,56"` (pt-BR) e `"1,234.56"` (en) viram `123456` centavos; `"12,5"` vira `1250`; `"0,1"` + `"0,2"` somam exatamente `30`; texto inválido ou mais de 2 casas decimais é rejeitado. Teste em Task 3 (`parseMoney_*`).
3. **Data de lançamento em fuso negativo ou positivo**: `"2026-03-31"` aparece como 31 de março e o mês continua março tanto em `America/Sao_Paulo` quanto em `Asia/Tokyo`. Teste em Task 3 (`formatBusinessDate_isTimezoneIndependent`, rodando com `TZ` diferentes).
4. **Trocar de `Account` (aceitar convite ou sair do casal)**: os tokens novos substituem os antigos e o cache do TanStack Query é limpo antes de navegar, para que nenhum dado da `Account` anterior apareça. Teste em Task 4 (`switchAccount_clearsQueryCache`) e Task 12 (`leave_replacesSessionAndClearsCache`).
5. **Lançamento de autor excluído ou com categoria/conta arquivada**: `createdBy = null` aparece como "Ex-membro" / "Former member"; uma referência arquivada continua visível com selo "Arquivada" / "Archived" e não aparece nos seletores de lançamento novo. Teste em Task 9 (`row_showsFormerMemberAndArchivedBadges`, `form_hidesArchivedOptionsForNew`).

### Task 4: Sessão, rotas, guardas e casca da aplicação

**Files:**
- Create: `src/shared/session/session-store.ts`; `src/app/router.ts`, `guards.ts`, `providers.ts`, `query-client.ts`; `src/app/layouts/AuthLayout.vue`, `AppLayout.vue`, `PublicLayout.vue`; `src/app/components/AppSidebar.vue`, `BottomNav.vue`, `UserMenu.vue`, `ThemeToggle.vue`; `src/app/pages/SuspendedPage.vue`, `NotFoundPage.vue`; `src/shared/lib/theme.ts`; `src/test/render.ts`
- Modify: `src/main.ts`, `src/app/App.vue`
- Test: `src/shared/session/session-store.spec.ts`, `src/app/guards.spec.ts`, `src/app/layouts/AppLayout.spec.ts`, `src/shared/lib/theme.spec.ts`

**Interfaces:**
- Consumes: `createHttp`, `ApiError`, `setLocale`, `AuthResponse`/`MeResponse`.
- Produces:
  - **Store `useSession`** (Pinia):
    - Estado: `accessToken: string | null`, `user: MeResponse | null`, `status: 'unknown' | 'anonymous' | 'authenticated'`.
    - `restore(): Promise<void>`. Chama `POST /auth/refresh` ao iniciar.
    - `applyAuth(r: AuthResponse): void`. Guarda o token e o usuário e chama `setLocale(user.locale)`.
    - `switchAccount(r: AuthResponse): void`. Faz `queryClient.clear()` e depois `applyAuth`.
    - `refresh(): Promise<boolean>`. Single-flight. Em `401 REFRESH_RACE`, espera 300 ms e tenta uma vez mais.
    - `logout(): Promise<void>`. Chama `POST /auth/logout`, limpa o estado e o cache, e navega para `/login`.
    - `isAdmin: computed`.
  - `http`: instância única de `createHttp` ligada ao store. Exportada de `src/app/providers.ts` como `useHttp()`.
  - **Rotas** (`meta`):
    - `public: true`: `/`, `/login`, `/register`, `/verify-email`, `/forgot-password`, `/reset-password`, `/invite/:token`, `/privacy`, `/terms`.
    - `requiresAuth: true`: `/onboarding`, `/dashboard`, `/transactions`, `/bank-accounts`, `/categories`, `/budgets`, `/recurring`, `/settings`, `/suspended`.
    - `requiresAdmin: true`: `/admin`.
    - Qualquer outra rota → `NotFoundPage`.
  - **`guards.ts`** — `beforeEach`:
    1. Aguarda `restore()` na primeira navegação.
    2. Rota autenticada sem sessão → `/login?redirect=<path>`.
